# 工具特化渲染：显示名 + 折叠内容 + 展开内容

| 项 | 内容 |
|---|---|
| 任务短名 | `tool-renderer-display-name` |
| 状态 | **已规划，待实施**（2026-11-14：方案见 [plan.md](plan.md)，实施记录见 [work.md](work.md)） |
| 范围 | `agent/lib`（C ABI / 注册表 / 渲染查询 / 缓存）、`agent/client`（TUI 工具行 + 占位行 + 中断分段）、内置渲染器与 4 个插件、测试、文档 |
| 目标 | 注册表改成 `<toolName, {displayName, 折叠内容渲染, 展开内容渲染}>`：显示名注册时确定（首帧可见），折叠与展开内容分开渲染、各自缓存，工具行头行骨架固定 |

## 目标（一句话）

工具行头行由主程序固定为 `+ [工具] <displayName> · <折叠内容>` / `- [工具] <displayName> <耗时>`，
插件只提供 `displayName` 与两段内容（折叠一行文本、展开 items），不再拼头行、不再给名字。

## 现状（要点）

- 注册项只有一个渲染回调，它同时产出**显示名 + 一行摘要 + 展开体 items**：
  - 显示名要等 client io 线程的回调，UI 首帧拿不到 → 占位行/工具行**把工具名藏起来**；
  - 展开体（Edit 的 diff、Plan 的图）每次渲染都要算，哪怕那一行是折叠的；
  - 折叠摘要各自带前导 `" · "`，TUI 再嗅探一次 `starts_with(" ·")`。
- 为补名字的延迟，有整套"名称结果"机制：按工具名多投递一次渲染请求、`lookupLatest("#工具名")`、
  两处 itemKey 版本项、中断 `prefetchInterruptToolNames`。
- 模版模式（`template_json` 里的 `displayName`/`summaryKey`，以及从未被读取的 `summaryTemplate`）
  是一套只够取单个参数的迷你 DSL。
- 展开头只有 decor 会换显示名，类型级渲染器命中时展开头仍是 `agentxx_filesystem_read`。

## 关键决策

1. 注册结构体：`{tool_name, display_name, collapsed_fn, expanded_fn, user_data}`；
   `display_name` 空则归一为 `tool_name`（命中项的显示名恒非空）。
2. **删掉内容输出里的 `displayName`**：名字只有一个来源；按调用改名/装饰用 `update_tool_decor`。
3. **删掉 `summaryKey` / `template_json`**：模版注册改成折叠内容回调（一行文本）。
4. 折叠内容与展开内容**两个回调、两份缓存、两套指纹**：展开体只在展开态查询，
   结果到达只让折叠条目失效。
5. 头行骨架固定：折叠 `+ [工具] <name> · <内容>`（失败结果首行 > 自定义折叠内容 >
   [未就绪则留空] > 默认渲染：运行中 `正在调用工具...` / 已有结果则结果），展开首行
   `- [工具] <name> <耗时>`、其后自定义 items 或默认展开体（参数 JSON + `正在调用工具...`/结果）；
   占位行 `{符号} [工具] <name> · 正在调用工具...`（单行、不可点击）。
6. 不兼容旧布局：接口代次保持 5（未发布），改结构体布局即可；必须重建插件产物。
7. 全部老逻辑一并清理：模版解析、`truncateToolSummary`、名称结果缓存、`" · "` 前导约定、
   中断预取、`starts_with(" ·")` 嗅探、`tool.running` 文案。

## 预期效果

| 场景 | 改前 | 改后 |
|---|---|---|
| 占位行（刚收到工具调用分片，工具行还没有） | `- [工具] 正在调用工具...`（名字藏起来、无 `·`） | `- [工具] Read · 正在调用工具...`（单行、不可点击） |
| 工具行首帧（折叠内容未就绪） | `+ [工具]  正在调用工具...` | `+ [工具] Read`（只有名字，内容到达再补 ` · `） |
| 工具行首帧展开（内容未就绪） | `- [工具] agentxx_filesystem_read` + 参数 + `正在运行...` | `- [工具] Read`（首行之后留空，items 到达再补） |
| 工具行无自定义渲染（或返回 null）· 运行中 | `+ [工具] Read ·` + 参数预览 | `+ [工具] Read · 正在调用工具...` |
| 工具行就绪（折叠） | `+ [工具] Read · [0, 100] /a.cpp` | 同（内容由折叠回调给，不带 `" · "`） |
| 工具行完成·无自定义 | `+ [工具] <toolName> <结果首行>`（无分隔） | `+ [工具] <toolName> · <结果首行>` |
| 展开（失败以外） | `- [工具] agentxx_filesystem_read 00:03` + items | `- [工具] Read 00:03` + items |
| 折叠行是否计算展开体 | 每次都算（diff/图） | 只有展开态才算 |
| 中断描述里的工具名分段 | 首帧常留空，靠 client io 预取 | 首帧即有 |

运行中的工具行同样用特化内容（内容到达就显示，不等工具完成）；`正在调用工具...`
只出现在占位行与默认渲染的运行中行；自定义内容还在算（`pending`）时该部分留空，
不用它顶替。
